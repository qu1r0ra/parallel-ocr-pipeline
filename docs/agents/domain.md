# Domain docs

This repository uses a single-context layout:
`GLOSSARY.md` at the root and decisions under `docs/adr/`.

## Before exploring

Read the glossary if present and any ADRs relevant to the work.
If absent, proceed silently; create them lazily when needed.

## Vocabulary and decisions

Use existing glossary terms in issues, specifications, and code discussion.
Surface conflicts with an existing ADR before proposing a different approach.

Keep glossary maintenance outside grilling interviews. Offer an ADR only
for a hard-to-reverse, surprising decision involving a real trade-off,
and write it after the user accepts.
